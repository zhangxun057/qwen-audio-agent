# 原子模型空间 Mock 索引

这是酒店语音 Gateway 对未来原子模型空间 MCP 的本地替身。租户由调用上下文隔离，实例 ID 不重复携带酒店 ID：

```text
room:2615
item:mineral-water
stay:20260825-zhang
order:20260825-zhang
```

## Gateway 快路径

| MCP 操作 | 作用 | 本地替身 |
| --- | --- | --- |
| `get_index` | 读取模型目录、静态实例别名、ID 规则和事件写入规范 | `index.json` |
| `search_instances` | 按房号等条件查询住店记录、订单等动态实例 | `instances.json` |
| `write_instance` | 解析明确对象、补系统信息并写入事件 | `atomic-records.json` |
| `query_instances` | 查询已写入事件 | `atomic-records.json` |
| `correct_instance` | 修改、重写或软删除已有事件 | `atomic-records.json` |

快路径不依赖 `get_meta_model`。事件最小输入和类别说明随 `get_index.writeContracts.event` 一次返回并按租户缓存。

这里的 `category + content` 是原子空间面向慢模型、系统触发和开放世界事项的底层兜底契约。当前语音快模型工具采用更严格的入口，额外要求 `factState` 和 `action`，以便先完成任务/事实分流并阻止已知动作绕过最低要件。

## 统一事件

事件只使用一个 `event` 元模型。快模型只选择四个直白类别：

| 类别 | 包含内容 |
| --- | --- |
| 物品 | 送出、消耗、借还、售卖、库存结果、拾获、交存 |
| 客人 | 投诉、要求、报失、偏好、住店变化、服务结果 |
| 酒店 | 房间设施、公共区域、交通天气、交接、恢复 |
| 其他 | 无法稳定归类的任何已发生事实 |

类别下面的“借出、投诉、拾获”等只是 `action` 值，不再建立十几个事件类型。最小写入只要求：

```json
{
  "category": "其他",
  "content": "今日夜班交接时需留意一楼入口处的临时指示牌"
}
```

`action`、`facts`、`entities` 都可选。能准确提取多少写多少；缺少它们不能阻断记录。

## 实体解析

- 房间号声明式拼接：`1501` 直接成为 `room:1501`，不要求房间预先出现在索引。
- 常见酒店物品按别名映射。特殊物品未建档时生成稳定的 `item:unresolved:<指纹>`，同时保留原名称。
- 楼层、电梯门口、走廊等地点是开放对象，不要求预建卡片。
- 住店记录和订单通过 `search_instances` 动态查询。查不到或无法唯一确定时，保留稳定的待解析引用，不让整条事实丢失。
- 录入人、租户、来源、记录时间、用户原话和幂等键由 Gateway 注入。

## 失物处理

- 客人报告丢失物品：类别“客人”，动作“报失”。
- 员工发现物品：类别“物品”，动作“拾获”。
- 不创建 `lostItemId`，不要求补房号。记录已知的物品描述、地点、住店记录或报告人即可。

## 任务边界

尚待执行的工作写任务；已经发生且无需派活的事实写事件。同一快模型轮次二选一。盘点是任务动作，盘点后得到的已核实数量、消耗或差异才写物品事件。
