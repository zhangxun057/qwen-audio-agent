# 酒店记事独立测试

这是给同事的最小测试入口，只验证“记事”本身：

- 记录类别和动作是否符合当前规则；
- 房间、物品、地点等自然名称能否映射到原子实例；
- 未预设的物品或开放地点能否先记录；
- 记录能否按房间、类别、关键词查询；
- 现场听错后能否修改或删除原记录。

它不依赖语音服务、Qwen/DashScope token、远程 WebSocket、3111/3113、PMS 或任务系统。页面直接调用项目中已有的原子空间 Mock 和 `LocalAtomicRecordStore`，所以测试结果就是当前记事代码的真实结果，不是另写的一套演示逻辑。

## 启动

在项目根目录执行：

```bash
npm install
node scripts/start-hotel-record-test.mjs
```

如果项目依赖已经安装，只执行第二行即可。

然后访问：<http://127.0.0.1:3121/>

也可以换端口：

```bash
HOTEL_RECORD_TEST_PORT=3122 node scripts/start-hotel-record-test.mjs
```

Windows PowerShell：

```powershell
$env:HOTEL_RECORD_TEST_PORT=3122; node scripts/start-hotel-record-test.mjs
```

记录会保存到 `runtime/hotel-record-test/records.json`。删除这个文件即可清空本地测试记录；不要把它和正式数据混用。

## 建议测试顺序

1. 点击“2015房送两瓶水”，保存后查询 2015，检查事实内容、`物品` 类别、`补入` 动作和矿泉水关联。
2. 点击“1015房借充电宝”，保存后查询 1015，检查房间、充电宝、数量是否都在记录里。
3. 点击“18楼电梯口捡皮鞋”，检查地点能否记录；这里不要求提前建立房间或失物编号。
4. 点击“携程订单投诉空调”，检查投诉必须带有可追踪的房间/客人/订单线索。
5. 从查询结果选中一条，修改内容，再查询确认原记录被重写而不是凭空新增一条；也可删除后确认默认查询不再显示。

## 和完整语音测试的边界

这个入口不测试快模型是否能从自然语音中判断“任务还是记事”，也不测试语音识别。那属于另一层，需要接同事自己的语音服务配置。把这份项目交给同事时，不需要附带任何 token；先用本页把记事规则和落库链路跑通即可。
